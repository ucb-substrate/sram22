This tutorial integrates an SRAM22 macro into a commercial Cadence flow:
synthesis with **Genus** and place-and-route with **Innovus**. As in the
[OpenROAD flow](/docs/tutorial/openroad/), the SRAM is a hard macro represented to the tools by
its `.lib` (timing) and `.lef` (abstract), with the `.gds` merged at the end.

## 1. Generate the macro views

```bash
sram22 --lef --lib
```

For a full (BWRC) install you can additionally run DRC/LVS/PEX on the macro
itself:

```bash
sram22 --all     # views + Calibre DRC, LVS, PEX
```

This produces `sram22_64x32m4w8.{gds,lef,lib,v}` (and, with `--lib`, timing for
multiple PVT corners such as `tt_025C_1v80`, `ff_n40C_1v95`, `ss_100C_1v60`).

## 2. Synthesis with Genus

Treat the macro as a leaf cell with timing. Read its Liberty alongside the
standard-cell libraries, and its LEF as physical information:

```tcl
# libraries
set_db library { sky130_fd_sc_hs__tt_025C_1v80.lib \
                 sram22_64x32m4w8.lib }
# physical (LEF) for physically-aware synthesis
read_physical -lef { sky130_fd_sc_hs.tlef \
                     sky130_fd_sc_hs.lef \
                     sram22_64x32m4w8.lef }

read_hdl   { top.v sram22_64x32m4w8.v }
elaborate  top
read_sdc   constraints.sdc
syn_generic && syn_map && syn_opt
write_hdl  > top_netlist.v
write_sdc  > top.sdc
```

<Aside type="note" title="Multi-corner timing">
  SRAM22 emits Liberty for several corners. Register all of them in your MMMC
  setup so Genus and Innovus check the SRAM under the same corners as the rest
  of the design.
</Aside>

## 3. Place-and-route with Innovus

<Steps>

1. **Initialize** the design with the macro LEF/LIB referenced in your MMMC and
   `init_design` view files.

   ```tcl
   set init_lef_file { sky130_fd_sc_hs.tlef sky130_fd_sc_hs.lef \
                       sram22_64x32m4w8.lef }
   set init_verilog  top_netlist.v
   set init_mmmc_file viewDefinition.tcl
   init_design
   ```

2. **Place and orient the macro.** SRAM22 macros must be placed **rotated by
   90°**. Use a legal orientation (R90, R270, or a mirror) and fix it:

   ```tcl
   place_inst u_mem 120.0 80.0 R90 -fixed
   ```

3. **Add power.** Connect `vdd`/`vss` (on **met2**) into the power grid with
   `add_rings` / `add_stripes`, then `route_special` over the macro.

4. **Place standard cells, run CTS, and route** (`place_opt_design`,
   `ccopt_design`, `route_design`).

</Steps>

<Aside type="caution" title="Legal orientations">
  Only the four 90°-rotated orientations are supported. Placing at R0/R180 will
  not match how the macro was designed and routed — see
  [Orientations](/docs/orientations/).
</Aside>

## 4. Signoff

<Tabs>
  <TabItem label="Timing">
    Run `timeDesign` / Tempus STA. The SRAM's setup, hold, and clk-to-Q arcs are
    taken from its `.lib`; see [Timing diagrams](/docs/interface/timing/) for what
    they represent physically.
  </TabItem>
  <TabItem label="Physical">
    Stream out the top-level GDS and merge the macro GDS
    (`sram22_64x32m4w8.gds`). Run Calibre DRC and LVS on the merged database. The
    macro is a `CLASS BLOCK` with `SYMMETRY X Y R90`.
  </TabItem>
</Tabs>

Your block now contains a placed, powered, and timed SRAM22 macro ready for
top-level integration.
